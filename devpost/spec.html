How this works, in plain language

One Python program you start by hand. It asks Discord for the Wild Wolves scheduled events in the next 7 days (using a small read-only bot), asks Outlook what is already on your calendar, drops events that are already there (same name and same start time), and adds the rest as tentative items. Then it prints the list. You decide in Outlook.

Outlook itself is the program's memory, so running twice never makes duplicates.

Components (click to open)

main.py — entry point and duplicate rule

Runs the steps in order, holds the rule "same name (ignoring capitals/spaces) + same start time in UTC = already there", prints results and plain error messages.

PRD: Run on demand · Skipping events already in Outlook · Result list · States and Boundaries

discord_events.py — Discord reader

GET /api/v10/guilds/{guild_id}/scheduled-events with Authorization: Bot …. Keeps events starting in the next 7 days; location from the event's location text or the channel name.

PRD: Finding events (next 7 days)

outlook_calendar.py — Outlook via Microsoft Graph

Sign-in with msal (browser once, token saved). Reads /me/calendarView for the window; creates events via POST /me/events with showAs: "tentative". End time defaults to start + 1 hour.

PRD: Skipping events already in Outlook · Creating tentative Outlook items

config.py — settings

Loads .env (bot token, server ID, Microsoft app ID) and stops with a clear message if something is missing. Secrets never go into chat or GitHub.

PRD: States and Boundaries

tests/test_dedupe.py — duplicate-rule checks

Same name + same time is skipped; same name + different time is kept.

Stack and where it runs

Python 3.11+, requests, msal, python-dotenv, pytest. Runs locally on your Windows laptop: python main.py. The required demo video and public GitHub repo don't need hosting.

Docs: Discord scheduled events · Graph calendarView · Graph create event · msal · requests

Simplified on purpose

  • Run by hand, not a daily 20:00 schedule.
  • Outlook is the only memory — no database.
  • Local run + recording, no hosting.
  • Test server first; Wild Wolves later by changing the server ID.
  • Moved events count as new.

Decisions and open items

Your choices: personal Outlook account · no personal-login scraping (a bot instead) · both a test server and an admin request · run locally · Python with plain requests + Graph/msal.

Your uncertainty: bots must be added by someone with server rights. Clarified in conversation; proven in the build when the bot lists the test server's events.

To check early in the build:

  • Accept/decline: on an item you create yourself, "accept" = change tentative → busy, "decline" = delete.
  • Exact bot permission needed; how recurring Discord events appear.
  • Whether a Wild Wolves admin adds the bot.
  • Current versions of msal/requests; Python 3.11+ installed.
